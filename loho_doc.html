A5 · ⭐ Cơ chế đồng bộ — phần quan trọng nhất

Nguyên lý

syncPush()  → POST {state, deletes}  → _mergeState2_()  → _APP_STATE
syncPull()  ← GET ?action=load       ← _readState_()    ← _APP_STATE
  • Tự động kéo về mỗi 3 phút (syncAutoPull, 180000 ms)
  • Bỏ qua khi: đang có thay đổi chưa lưu · đang gõ vào ô nhập · đang mở popup
  • Tự đẩy lên sau 1,5 giây kể từ thay đổi cuối (syncSchedule, debounce)

Hai chế độ gộp

(1) Mục có khoá gộp — gộp theo TỪNG bản ghi

Định nghĩa ở MERGE_KEYS (Apps Script) và SYNC_MK (app) — phải khớp nhau:

orders  : 'o:'   + madon + '|' + sku
nx      : 'nx:'  + ma
sonLe   : 'sl:'  + id
xnb     : 'xnb:' + id
xhd     : 'xhd:' + id
products: 'p:'   + code
ton     : 't:'   + code
gifts   : 'g:'   + id        // bổ sung sau
huHong  : 'hh:'  + id        // bổ sung sau

Quy tắc: cùng khoá → bản ghi có _ts lớn hơn thắng. Khác khoá → giữ cả hai.

(2) Mục KHÔNG có khoá gộp — so dấu thời gian _kts

Các khoá hoan, skumap, kkHistory, kyArchive, cats, bom, tonKy, tonPts, weekCheck… là object nguyên khối.

  • App ghi DATA._kts[<khoá>] = Date.now() mỗi khi khoá đó đổi
  • Server so _kts: bên nào mới hơn thì giữ
  • Máy chạy code cũ (chưa có _kts) không ghi đè được bản mới

(3) Kiểm kho (kk)

Cơ chế riêng _mergeKK_: LWW theo từng SKU, có tombstone, không bao giờ xoá trắng.

Xoá bản ghi

App so SYNC.base (ảnh chụp lần đồng bộ trước) với DATA hiện tại → khoá nào biến mất thì đưa vào deletes → server đánh dấu _del = true + _ts = delTs.

Thẻ _del chặn máy cũ làm bản ghi sống lại. App lọc bỏ _del khi tải về.

A7 · Logic kỳ kế toán & tồn kho

Chu kỳ

Chốt ngày 25, kỳ mới bắt đầu ngày 26. Ví dụ: kỳ 2026-09 = từ 26/08 đến 25/09.

Hàm: curKyYm() · _nextYm() · _chotTs() · _ymOfDate()

Công thức tồn

function tonCalc(r){
  var out = r.nb + r.hd + r.bh + r.qt + r.sx + (r.hh || 0);
  var ton = r.dk + r.moi - out;
  return { out: out, ton: ton };
}
MãÝ nghĩa
dkTồn đầu kỳ
moiNhập kho
bhXuất bán hàng
nbXuất nội bộ
hdXuất hoạt động
qtXuất quà tặng
sxXuất sản xuất
hhXuất hàng hư hỏng (bổ sung sau)

Ba hàm tính tồn

HàmDùng cho
computeTon()Kỳ hiện hành, không giới hạn trên. Có cache theo _dataVer
computeTonMonth(mon)Xem theo tháng cụ thể (có cửa sổ thời gian)
computeTonWindow(startTs, endTs, seedDk, seedMoi)Khoảng thời gian bất kỳ

Kỳ theo từng mã: mỗi SKU có mốc kỳ riêng (tonPts[code], tonKy[code]) — cho phép đóng kỳ từng phần, không bắt buộc đóng cả kho cùng lúc.

Quy trình đóng kỳ — 3 bước, đúng thứ tự

  1. ① Chốt kiểm kho 📷 — chụp tồn lý thuyết, ghi chotTs = Date.now() (đúng giây bấm)
  2. ② Tạo bản kiểm kho — nhập số đếm → ✓ Xác nhận số lượng cuối cùng (cấp lệnh LKK-xxxx)
  3. ③ Đóng kỳ & chuyển kỳ 🔒 — lưu kyArchive[ym], đặt tồn thực tế thành đầu kỳ mới, gắn tonKy = kỳ sau
Lưu ýMốc chotTs chia ranh giới kỳ theo giờ xuất thực tế của đơn (_ct), không theo ngày đặt hàng.

Nhập số đếm theo Lẻ + Thùng

Ô Kiểm 1/2/3 cho nhập: Lẻ + nhiều dòng [số thùng] × [quy cách], tự cộng tổng. Quy cách lưu ở DATA.kkQC[code], lần sau tự điền.

Cờ nghi vấn tự động (kkNVauto): KK1≠KK2 · lệch tồn vượt ngưỡng (DATA.kkCfg) · đếm 0 mà sổ có · nghi đếm thùng thay vì đơn vị lẻ (đếm × quy cách ≈ sổ).

A8 · ⭐ Sự cố đã gặp & nguyên nhân

Đọc kỹ phần này trước khi sửa bất cứ gì

Sự cố 1 — Mất dữ liệu do đồng bộ đa máy

Triệu chứng: chương trình quà tặng / tồn kho / hoàn hủy biến mất sau khi máy khác đồng bộ.

Nguyên nhân: ~37 khoá cấu hình bị ghi đè nguyên khối — máy nào đẩy sau thì thắng, kể cả máy giữ dữ liệu cũ.

Đã sửa: thêm _kts (dấu thời gian từng khoá) + _mergeState2_ ở backend.

Còn lại: mọi máy phải chạy cùng phiên bản code.

Sự cố 2 — Chương trình quà tặng nhân bản (64 bản)

Nguyên nhân kép:

  1. Sau khi đưa gifts vào nhóm gộp theo bản ghi → hợp nhất (union) → tích tụ, không tự xoá
  2. Hàm khoiPhucQuaTang() so khớp theo id, nhưng chương trình cũ trong backup không có id → không nhận ra trùng → thêm mới

Hậu quả: nhiều bản cùng "Đang chạy" → 1 đơn được tặng quà nhiều lần.

Đã sửa: gộp trùng theo chữ ký (tên + ngày + giờ + bậc + quà), 64 → 20 chương trình.

⛔ KHÔNG chạy lại khoiPhucQuaTang()

Sự cố 3 — Lệch kỳ tháng 7 (tồn âm, doanh thu biến mất)

Nguyên nhân: chotTs bị script nạp dữ liệu cũ ghi đè thành 25/06 10:30 — bằng đúng mốc đầu kỳ → cửa sổ tính tồn co về rỗng.

Đã sửa:

  • Nút "📷 Chốt kiểm kho" giờ ghi đúng giây bấm, bỏ ô "Ngày chốt" (trước đây lấy theo ngày chọn → dễ sai)
  • Ảnh tồn tháng 7 dựng lại bằng cách suy ngược từ đầu kỳ tháng 8 (số đếm tay thực tế):
    đầu T7 = đầu T8 − nhập T7 + xuất T7
  • Lưu arch + archYm trên từng dòng tồn để không bị ghi đè

Sự cố 4 — Hệ thống nặng, đứng máy

Nguyên nhân: 28.680 dòng đơn ≈ 11,2 MB JSON. Mỗi thao tác đều JSON.stringify toàn bộ.

Đã xử lý: lưu trữ đơn cũ (xem A9). 11.243 KB → 4.412 KB.

Sự cố 5 — Xuất Excel thiếu dữ liệu

Nguyên nhân: XLSX.utils.table_to_book() chỉ lấy text hiển thị, không lấy giá trị ô <input>/<select>. Số dạng 11.157 bị hiểu thành 11,157 (thập phân).

Đã sửa: exportXLSX() clone bảng, đọc .value của ô nhập, chuyển số Việt Nam sang số thật (_xlNum), giữ mã đơn ≥12 chữ số dạng chữ.

Sự cố 6 — File HTML bị cắt cụt khi sửa

Nguyên nhân: công cụ sửa file tự động bị giới hạn kích thước với file ~600 KB.

Cách làm đúng: sửa bằng script (Python/Node), sau đó luôn kiểm tra:

node -e 'const fs=require("fs"),vm=require("vm");
const h=fs.readFileSync("index.html","utf8");
const m=[...h.matchAll(/<script\b[^>]*>([\s\S]*?)<\/script>/gi)].map(x=>x[1]).join("\n;\n");
new vm.Script(m); console.log("OK", m.length);'

A9 · Lưu trữ đơn cũ (làm nhẹ hệ thống)

File luutru.gs, biến LT_GIU_THANG = số tháng giữ lại trong app.

Quy trình 5 bước — tự dừng nếu lỗi

  1. Backup toàn bộ state ra Drive — lỗi thì dừng, không đụng gì
  2. Tính & lưu thangTom (tóm tắt doanh thu từng tháng)
  3. Ghi chi tiết đơn cũ ra tab DonHang_LuuTru (16 cột)
  4. Đếm lại số dòng đã ghi — thiếu thì dừng, không xoá gì
  5. Thay đơn cũ bằng thẻ _del (~60 byte thay vì ~430 byte)
HàmTác dụng
XEM()Xem trước: dung lượng, số đơn từng tháng, tháng nào đã/chưa đóng kỳ
CHAY_LUU_TRU()Chạy dọn thật
DON_THE()Xoá hẳn thẻ _del — chỉ chạy khi mọi máy đã Tải lại
Sau khi dọn vẫn xem được Tổng quan doanh thu từng tháng (từ thangTom) · Theo dõi tồn từng mã theo tháng (từ kyArchive) · Chi tiết đơn cũ (tab DonHang_LuuTru)

Khuyến nghị: chạy CHAY_LUU_TRU() mỗi 2–3 tháng.

B2 · Bẫy dữ liệu cần nhớ

  • Không dùng sheet "Tổng hợp" — số liệu không chính xác
  • Không dùng sheet raw để tính tổng doanh thu — mỗi SKU 1 dòng → cộng trùng
  • Lazada: cột 0 là createTime, không phải mã đơn. Mã đơn ở cột 4 (orderNumber)
  • Web + Lazada 2026: tên sản phẩm trống ở sheet đã xử lý → phải lấy từ sheet raw, map qua mã đơn
  • TikTok 1: có 2 dòng header → bỏ qua 2 dòng đầu
  • Định dạng ngày khác nhau: Shopee YYYY-MM-DD HH:MM · TikTok DD/MM/YYYY HH:MM:SS · Web raw DD/MM/YYYY · Lazada raw DD Mon YYYY HH:MM
  • Số Việt Nam: 108.000 → 108000 (nếu sau dấu chấm đúng 3 chữ số → là phân cách nghìn). Năm có thể là 2.025 hoặc 2025

C1 · Quy trình triển khai code mới

Frontend (index.html)

  1. Trong app: ☁ → Sao lưu ngay, đợi "Đã sao lưu"
  2. Up file mới lên GitHub (ghi đè index.html)
  3. Đợi 1–2 phút cho GitHub Pages cập nhật
  4. Mọi máy: F5 → ☁ Tải lại từ Sheets

Backend (Apps Script)

  1. Sửa code → Ctrl+S
  2. Triển khai → Quản lý các bản triển khai → ✏️ → Phiên bản: Mới → Triển khai
Lưu ýKhông tạo deployment mới — URL sẽ đổi, app mất kết nối.

C2 · Kiểm tra sức khoẻ hệ thống

Dán vào Console trình duyệt (F12):

(function(){
  var kb = Math.round((localStorage.getItem('loho-kho')||'').length/1024);
  var live = (DATA.orders||[]).filter(function(o){return !o._del;}).length;
  return JSON.stringify({
    dungLuongKB : kb,
    donSong     : live,
    theDanhDau  : (DATA.orders||[]).length - live,
    sanPham     : (DATA.products||[]).length,
    quaTang     : (DATA.gifts||[]).length,
    quaDangChay : (DATA.gifts||[]).filter(function(g){return g.tt==='Đang chạy';}).length,
    kyDaDong    : Object.keys(DATA.kyArchive||{}),
    kyHienHanh  : (typeof curKyYm==='function' ? curKyYm() : '?'),
    dongBo      : { bat: SYNC.on, lanCuoi: SYNC.last, trangThai: SYNC.status }
  }, null, 2);
})()
